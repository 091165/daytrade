# Daytrade Signal Board

日経225デイトレ・スキャルピング向けの毎朝の寄り前シグナルを自動計算するダッシュボード。
GitHub Actions で平日の寄り前（6:37 / 7:07 / 7:37 JST）に実行、GitHub Pages で配信。
定期実行は混雑で遅れることがあるため、9:00以降に遅れて動いた分は寄り前の版を上書きしない。寄り前に1度も間に合わなかった日は、ページ上部に注意を出す。
GitHub の定期実行は数時間遅れたり飛ばされたりするため、`.github/workflows/preopen_kick.yml` が夜中（1:17 / 3:17 / 5:17 JST）に動き出して 6:40 まで待ち、毎朝の判定を手動実行する（夜中の予約が遅れても寄り前に間に合う）。

## 提供するシグナル

### 1. 朝一先物鞘取りシグナル（最重要）
- 現対（日経先物 − 日経現物）が **±1,000円以上** のハイボラ時に発動
- 現対が +1,000円超 → **鞘取りショート**（先物高 → 先物売りで閉じる方向を狙う）
- 現対が -1,000円超 → **鞘取りロング**（先物安 → 先物買いで閉じる方向を狙う）
- ±1,000円以内 → **ニュートラル**（様子見）

### 2. キリバン値幅（前日終値 ± N円）
- 前日終値に対して ±500 / ±1,000 / ±1,500 円の水準を算出
- これらがレジサポ・天底の目安になりやすい
- **ハイボラ時のみ機能しやすい**（低ボラ時は普通の移動平均で十分）

### 3. 株価キリバン節目（丸い数字）
- 現在価格の上下で最も近い 1,000円単位の水準を算出
- 常にレジサポ候補。軟調相場ほど機能しやすい

### 4. 米日連動判定（前日米国市場 vs 先物）
- ナスダック・SOXの騰落率を表示
- 米強日弱／非連動の検出用

### 5. 今日のマイルール（ページ最上部）
- その日の判定に合わせて、守るルールを大きく表示する
- **買いポジ主体／売りポジ主体（トレンド日）**: 「全部◯◯で統一・逆張り禁止・即損切り」を赤で強調
  - 過去のトレード記録では、方向が当たった日ほど逆張り・塩持ちで大きく負けていたため
- **初心者手出し無用**: 「承認銘柄だけ・09:05〜09:15は様子見」
- 毎日のルール（10時前終了、1日-1万円で終了、株数は100株まで、2連敗で終了、承認外銘柄禁止、日計り確認）は常に表示
- 文言は `src/trading_rules.py` の定数を書き換えれば変わる

### 6. 承認銘柄の寄り前予測（フジクラ・SBG）
- 前日の米国関連株の平均騰落率から、各銘柄の方向を出す
  - フジクラ: GLW・COHR・LITE・VRT（光ファイバー・AIデータセンター）
  - ソフトバンクG: ARM・NVDA・QQQ
- **「窓（前日終値→寄り）」と「寄り後（寄り→引け）」を分けて検証・表示**する
  - 米国の動きは主に窓に出る。デイトレで取れるのは寄り後だけなので、
    寄り後の連動が弱ければ「寄り後の方向は読めない」とそのまま表示する
- 指数の判定と逆向きの銘柄には「今日は見送る候補」と警告を出す
- 検証は週次バックテスト（`src/focus_backtest.py`）で行い、結果がまだない間は「未検証」と表示する

### 6a. 試用銘柄（村田製作所）
- 承認銘柄と同じカードで寄り前予測・想定値幅を出し、「試用」と表示する（米関連株: SOXX・QQQ・NVDA）
- 条件: **100株だけ・10時前だけ・-5,000円で即損切り**。値動きは承認銘柄の約2倍（9時台の値幅 約5.3%）
- 2026-10-29 から、条件どおりの取引が20回たまったら承認するか決め直す（daytrade-journal の振り返りページで集計）
- 試用銘柄は `src/trading_rules.py` の `_TRIAL` と `src/focus_stocks.py` の `trial=True` で管理

### 6b. 想定値幅（フジクラ・SBGのカード内）
- 直近10営業日の平均値幅（高値−安値）から、今日の値幅を円で表示（100株あたりも）
- 「荒れた日（5日に1日）」の幅、損切り-5,000円が値幅の何割にあたるか、最近の値幅が普段より大きいか
- 未完成の今日の足（自動実行が場中にずれ込んだ場合）は計算に使わない
- 当たり具合は週次バックテスト（`src/expected_range.py` の `validate_range_prediction`）で検証
- 利確の目安：損切り幅の3倍（`trading_rules.REWARD_RISK_RATIO`）。9時台の目安より大きければ「10時までに届きにくい」と出す（表示だけ）

### 6b-1. 銘柄ごとのページ（`docs/stock/<コード>.html`・`src/stock_page.py`）
- トップページのカードは短いまとめ（方向・損切り／利確・いちばん近い目安）にして、くわしくは銘柄ページへ
- 銘柄ページは上から：今日の作戦と物差しの図（入った値段から損切り・利確までと、9時台にふつう動く幅を同じ縮尺で）→ 日足に上値・下値の目安と今日の帯を重ねた図 → 値幅 → 寄り前予測 → 注意 → 今日の警告 → マイルール

- **場中モード**（銘柄ページ）：入った値段と買い／売りを入れると、損切り（逆指値）と利確（指値）の値段を出す。損切り・利確を押してその日の記録をつけると、回数・損益・連敗・1日の上限までの残りを出し、2連敗・-1万円・10:00 のどれかで「今日は終了」と赤く表示する。記録はその端末のブラウザにだけ保存（日付ごと・全銘柄で共有）

### 6b-2. 今日の作戦（承認・試用銘柄のカード内、`src/trade_plan.py`）
- 100株の損切り・利確の幅：9時台の目安を3つに分けた幅を損切り（上限 -5,000円）、その3倍を利確
  - 上限に当たる銘柄は「損切りが近い（振り回されやすい）」、決算明けは「見送り候補」と出す
- 上値・下値の目安（前日の高値・安値、5日・20日の高値・安値、25日線、キリのいい値段）を前日終値から近い順に
- 2026/11/1 の検証（`src/level_study.py`・売買代金上位20銘柄・5分足60日・9時台）：どの水準も、ただの値段（止まった割合 43%）と比べて止まりやすくはない。5日高値はむしろ抜けやすい（止まったのは 32%）。止まる場所ではなく、損切り・利確の位置を決める目安として出す
- 週次レポートに「ルールに合う銘柄」：売買代金上位を同じルールに当てはめ、◎（損切りが -3,000〜-5,000円に収まる）＝SBG・フジクラ・古河電工・データセクション、△（値動きが大きすぎる）＝村田・キオクシアなど

### 6b-3. 米関連株が大きく動いた翌日の値幅（`src/us_range_study.py`・週次）
- 前日の米関連株の平均の動きの大きさ（1%未満／1〜2%／2〜3%／3%以上）ごとに、翌日の値幅が目安（10日平均）の何倍だったかを比べる。決算明けは除く
- 2026/11/1 の結果（5年分）：3%以上動いた翌日でも 1.07〜1.08倍（1%未満の日は 0.97〜1.00倍）で、補正後に偶然と区別できる差はない（q=0.12〜0.18）→ 値幅の目安はそのまま
- 毎週の結果で効く区分が出てきたら、その朝だけ値幅と作戦の幅にその倍率を掛ける（銘柄ページの「値幅」に、今日の区分と検証結果を出す）

### 6c. 9時台の値幅の目安・決算明けの注意（承認・試用銘柄のカード内）
- `src/morning_range.py`。9時台（9:00-10:00）の値幅の目安を「1日の目安 × 銘柄ごとの比」で円に直して出す
  - 2026/10 の検証（20銘柄・5分足60日）: 1日の目安から9時台の値幅は r=0.74 で当たる。米国株の動きの大きさや窓を足しても大きくは変わらない
- 9:10の確認：寄り直後10分の動きが大きい日は、9時台の値幅も広がりやすい（全銘柄まとめの表から、目安の何倍になるかを出す）
- 決算明け（前営業日の引け後〜寄り前に発表）なら、過去の決算明けの値幅が目安の何倍だったかを出して注意する。次の決算日も表示
- 比は週次バックテストで更新（レポートの「🌅 9時台の値幅・決算明けの検証」）

### 5a. 節目（大台）とレンジ型の日（トップページ）
- 「📏 節目（大台）」：日経平均・日経レバ（1570）・Wインバース（1357）の前日終値の上下でいちばん近い 1,000円の大台までの距離（10,000円の倍数は「大台」と表示）。`src/kiriban.py` の `build_big_levels`
- 見出しに、その日の判定に合わせた使い方を1行（買い：下の節目の買いが中心／売り：上の節目の売りが中心／手出し無用：上下の節目で逆張り）。トレンド日に出すのは判定と同じ向きの売買だけ
- 「🔁 レンジ型の日」：米3指数がすべて ±0.5% 未満・現対 ±100円以内で、判定が手出し無用の日だけ、マイルールの下に出す（`market_direction.build_range_day`）。承認・試用銘柄が決算明けの日と、トレンド日には出さない。検証で確かめられるまで「未検証」と表示
- 検証：週次レポートの「📏 大台・節目は止まりやすいか」（1分足で、大台に初めて触れたときと2回目以降・比較用の値段・判定別）と「⏱️ 節目ごとの方向」の中の「レンジ型の日」
- 1分足の保存（`collect_minutes.py`）に、日経平均（N225）と 1357 を追加。保存済みの日にも、29日前までさかのぼって足す

### 6d. 最高値を更新中の表示（承認・試用銘柄のカード内、`src/stock_trend.py` の `at_high`）
- 前日までの確定足で、直近5営業日のうちに52週（250営業日）の高値を超えていたら「52週高値を更新中（買いの順張りが入りやすい）」を1行。日足より前の最高値（月足・上場来）も超えていれば「上場来高値を更新中」
- 指数が「売りポジ主体」の日に高値更新中なら「指数は売り判定だが、この銘柄は高値更新中：売りは見送り候補」を赤で出す（買いを勧める表示にはしない）
- 検証は週次レポートの「🎯 承認銘柄・試用銘柄の個別予測の検証」の中（5年分。高値更新中の日とそうでない日の寄り後に上げた割合）

### 6d-2. 株価の大台の手前・節目を少し割ったところ（承認・試用銘柄のカード内、`src/round_study.py`）
- 前日終値が大台（1,000円・10,000円・5,000円の倍数）の ±3% 以内なら「大台 10,000円の手前：いったん止まりやすい（突破すれば強い）」を1行。週次レポートで、大台の手前から5日以内に抜けた割合を比較用の値段と比べて添える
- 1,000円の節目を割ったあと 0.5% より下に行かずに戻った割合を、1分足で比較用の値段と比べる。差がはっきりしたときだけ「急落時の反発候補：節目と その少し下」を出す（それまでは出さない）

### 6e. 決済方法の比較（研究用・週次レポートのみ、`src/exit_study.py`）
- 承認・試用銘柄の5分足（Yahoo・60営業日）で、判定の向きに 9:05 で入った場合の3通りを比べる：(a) 10時終了（今のルール）／(b) 時間方式（10時に含み益なら逆指値を置き直して引けまで）／(c) 1：3（-5,000円・+15,000円の OCO）
- 平均・中央値・勝率・最大連敗・最大ドローダウン・-1万円に触れた日数を、判定別・確度別・銘柄別に。件数が少ないので95%区間つき。同じ5分足で損切りと利確の両方に触れたら損切りが先とみなす
- daytrade-journal の振り返りメモ（`realTrades`）に時刻つきの約定がある日は、実際の取引と (a) の差も出す
- 毎朝の画面とマイルール（`trading_rules.py`）は変えない。利確の目安（損切り×3）の表示を続けるかは、この結果を見てユーザーが決める

### 6f. ゴールドを方向の材料に入れる検証（研究用・週次レポートのみ、`src/gold_study.py`）
- 前日のゴールド先物（GC=F）の騰落を「下げ＝上げ材料」の固定の符号で数えた版と、直近60営業日の「日経の寄り→引け」との相関の符号を使う版（|r|<0.1 の期間は使わない）を比べる
- ゴールドだけで入った場合／v2 にゴールドが逆なら見送る条件を足した場合／7材料の一致数ごと。p値は記事の考え方の検証の BH 補正にまとめる
- 効かなければ判定には入れない（毎朝の判定は変えていない）

### 7. 米国株 × 日本株 連動スキャン（研究用・週次レポートのみ）
- 売買代金上位の日本株11銘柄 × 米国株25銘柄（半導体・メモリ・AIデータセンター・光通信・電子部品・指数）を総当たりで検証
- 各組み合わせで「窓」と「寄り後」の相関を測り、日本株ごとに連動の強い米国株を表示
- 数百組を同時に調べると偶然の当たりが出るため、Benjamini-Hochberg法で補正し **q<0.05** のみ有意とする
  - 純粋なノイズでの試験: 補正なしだと毎回平均14組が偽の当たり、q<0.05では30回中0回
- **毎朝のダッシュボードには出さない**（承認銘柄以外を触るきっかけを作らないため）
- 銘柄の入れ替えは `src/correlation_scan.py` の `SCAN_JP` / `SCAN_US` を編集

### 8. 日付ごとの記録（振り返り用）
- 毎朝の判定一式を `docs/archive/YYYY-MM-DD.json` に残し、日付一覧を `docs/archive/index.json` に書く
- 寄り前に作られた版がある日は、寄り後の版で上書きしない（トレード前に見ていた判定を残すため）
- `trading_rules.checks` に、約定記録と機械的に突き合わせられる形のルールを入れる
  （承認銘柄・1日の損失上限・終了時刻・日計り・方向・1回の損切り幅・株数・様子見の時間帯・連敗で終了）
- `history.json` にあって記録がない日は、判定ラベルから今のルールで組み立て直して埋める（`reconstructed: true`）
- [daytrade-journal](https://github.com/091165/daytrade-journal) の `review.html` がこれを読み、
  その日のルールを守れたかと成績を表示する

### 7b. 売買代金上位の銘柄スクリーニング（研究用・週次レポートのみ）
- `src/stock_screen.py`。連動スキャンの11銘柄に、売買代金ランキング11〜20位の9銘柄を足した20銘柄が対象
- 寄り後（寄り→引け）の方向を、寄り付き時点でわかる3つの手がかりで当てられるかを調べる
  - 米国株の前日の動き（銘柄ごとに前半の期間で一番連動した米国株）・その日の窓・前日の寄り後
- 過剰な当てはめを避けるため、2年を前半・後半に分け、前半で向きを決めて後半だけで当たりを測る。
  後半のp値は全銘柄×全手がかりで BH 補正し、q<0.05 かつ前半と同じ向きのものだけを「信頼できる」とする
- あわせて値幅予測の当たり具合（r）・1日の値幅・売買代金を並べる
- 毎朝のダッシュボードには出さない。承認・試用の候補探しに使う

### 7c. 節目ごとの方向（研究用・週次レポートのみ）
- `src/checkpoint_study.py`。寄り・9:05・9:15・9:30・10:00 の節目で区切り、寄り→9:05／9:15／9:30／10:00 と 9:05／9:15／9:30→10:00 の動きの向きを、
  米国株の前日の動き・窓・前日の寄り→引け・寄り→区間の始まりまでの動き で当てられるかを調べる
- 寄り値は日足の始値、各節目の値段はその時刻に始まる5分足の始値（Yahoo の分足は 9:00〜9:05 の足が欠ける日が多いため）
- 全銘柄まとめは日ごとに銘柄平均をとって日数で検定（同じ日の銘柄どうしが一緒に動く影響を避ける）、銘柄ごとは BH 補正
- ※ カードの「寄り後」は寄り→引け（15:30）のこと。節目ごとの結果はこのレポートで見る
- 1分足は `src/collect_minutes.py` が平日の引け後に `data/minutes/YYYY-MM-DD.csv`（9:00〜10:29、20銘柄）へ貯める（`.github/workflows/collect_minutes.yml`）
- 1分足は Yahoo のチャートデータを直接取る（`src/yahoo_chart.py`）。出来高が入り、9:00 の足がある日はそれも入る
- ⚠️ Yahoo の分足は寄りの 9:00〜9:05 が欠ける日が多い（無料データの限界）。そのため「寄り」は最初に取れた足（9:04〜9:06ごろ）として扱う。寄り直後の数分を正確に調べるには、証券会社のAPIなど有料・口座連携のデータが必要

### 7d. フィボナッチの水準で反発しやすいか（研究用・週次レポートのみ）
- `src/fib_study.py`。38.2%・50%・61.8% の反発率を、比較用の水準（30%・45%・55%・70%）と比べる
- 線の引き方は2つ：①窓（前日終値〜寄り値、±1%以上の日）②寄り後30分（9:00〜9:30）の高値〜安値
- 線に初めて触れたあと、幅の15%だけ戻したら「反発」、先に進んだら「抜けた」（前場の引けまで）
- 差の95%区間は (銘柄, 日) 単位のブートストラップで出す。1分足が40日分たまったら1分足に切り替わる

### 7e. メンサロ記事の考え方の検証（研究用・週次レポート）
- 雇用統計の結果は `data/us_events.csv`（`date,event,result`。例 `2026-11-06,nfp,good`）に手で書く。日付を書かなければ第1金曜とみなす
- `src/idea_study.py`。日経平均と承認・試用銘柄の日足（2019年〜）で、記事の考え方を寄り→引けで確かめる。BH法で補正
- 2026/10/31 の結果（2019/1〜2026/10・1,906日）

## アーキテクチャ

```
daytrade-signal-board/
├── src/
│   ├── kiriban.py        # 計算コア（純粋関数のみ、I/Oなし）
│   ├── fetch_data.py     # yfinance データ取得
│   ├── dashboard.py      # HTML生成
│   └── main.py           # エントリポイント
├── tests/
│   └── test_kiriban.py   # 計算ロジックのユニットテスト
├── docs/                 # GitHub Pages配信用（自動生成）
│   ├── index.html
│   └── signal.json
├── .github/workflows/
│   └── daily_signal.yml
└── requirements.txt
```

**設計方針**: 計算ロジック (`kiriban.py`) は純粋関数で、データ取得と完全に分離。
これでバックテスト・ユニットテストが書きやすく、将来別のデータソース
（Rakuten / SBI / J-Quants）に切り替えるのも容易。

## ローカル実行

```bash
pip install -r requirements.txt
python src/main.py              # docs/index.html と docs/signal.json を生成
python tests/test_kiriban.py    # テスト
```
