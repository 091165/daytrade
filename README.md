# Daytrade Signal Board

日経225デイトレ・スキャルピング向けの毎朝の寄り前シグナルを自動計算するダッシュボード。
GitHub Actions で毎朝 8:40 JST に実行、GitHub Pages で配信。

## 提供するシグナル

### 1. 朝一先物鞘取りシグナル（最重要）
- 現対（日経先物 − 日経現物）が **±1,000円以上** のハイボラ時に発動
- 現対が +1,000円超 → **鞘取りショート**（先物高 → 先物売りで閉じる方向を狙う）
- 現対が -1,000円超 → **鞘取りロング**（先物安 → 先物買いで閉じる方向を狙う）
- ±1,000円以内 → **ニュートラル**（様子見）

### 2. キリバン値幅（前日終値 ± N円）
- 前日終値に対して ±500 / ±1,000 / ±1,500 円の水準を算出
- これらがレジサポ・天底の目安になりやすい
- **ハイボラ時のみ機能しやすい**（低ボラ時は普通の移動平均で十分）

### 3. 株価キリバン節目（丸い数字）
- 現在価格の上下で最も近い 1,000円単位の水準を算出
- 常にレジサポ候補。軟調相場ほど機能しやすい

### 4. 米日連動判定（前日米国市場 vs 先物）
- ナスダック・SOXの騰落率を表示
- 米強日弱／非連動の検出用

### 5. 今日のマイルール（ページ最上部）
- その日の判定に合わせて、守るルールを大きく表示する
- **買いポジ主体／売りポジ主体（トレンド日）**: 「全部◯◯で統一・逆張り禁止・ロット半分・即損切り」を赤で強調
  - 過去のトレード記録では、方向が当たった日ほど逆張り・塩持ちで大きく負けていたため
- **初心者手出し無用**: 「承認銘柄の100株だけ・09:05〜09:15は様子見・2連敗で終了」
- 毎日のルール（10時前終了、1日-1万円で終了、承認外銘柄禁止、日計り確認）は常に表示
- 文言は `src/trading_rules.py` の定数を書き換えれば変わる

### 6. 承認銘柄の寄り前予測（フジクラ・SBG）
- 前日の米国関連株の平均騰落率から、各銘柄の方向を出す
  - フジクラ: GLW・COHR・LITE・VRT（光ファイバー・AIデータセンター）
  - ソフトバンクG: ARM・NVDA・QQQ
- **「窓（前日終値→寄り）」と「寄り後（寄り→引け）」を分けて検証・表示**する
  - 米国の動きは主に窓に出る。デイトレで取れるのは寄り後だけなので、
    寄り後の連動が弱ければ「寄り後の方向は読めない」とそのまま表示する
- 指数の判定と逆向きの銘柄には「今日は見送る候補」と警告を出す
- 検証は週次バックテスト（`src/focus_backtest.py`）で行い、結果がまだない間は「未検証」と表示する

### 6b. 想定値幅（フジクラ・SBGのカード内）
- 直近10営業日の平均値幅（高値−安値）から、今日の値幅を円で表示（100株あたりも）
- 「荒れた日（5日に1日）」の幅、損切り-5,000円が値幅の何割にあたるか、最近の値幅が普段より大きいか
- 未完成の今日の足（自動実行が場中にずれ込んだ場合）は計算に使わない
- 当たり具合は週次バックテスト（`src/expected_range.py` の `validate_range_prediction`）で検証

### 7. 米国株 × 日本株 連動スキャン（研究用・週次レポートのみ）
- 売買代金上位の日本株11銘柄 × 米国株25銘柄（半導体・メモリ・AIデータセンター・光通信・電子部品・指数）を総当たりで検証
- 各組み合わせで「窓」と「寄り後」の相関を測り、日本株ごとに連動の強い米国株を表示
- 数百組を同時に調べると偶然の当たりが出るため、Benjamini-Hochberg法で補正し **q<0.05** のみ有意とする
  - 純粋なノイズでの試験: 補正なしだと毎回平均14組が偽の当たり、q<0.05では30回中0回
- **毎朝のダッシュボードには出さない**（承認銘柄以外を触るきっかけを作らないため）
- 銘柄の入れ替えは `src/correlation_scan.py` の `SCAN_JP` / `SCAN_US` を編集

## アーキテクチャ

```
daytrade-signal-board/
├── src/
│   ├── kiriban.py        # 計算コア（純粋関数のみ、I/Oなし）
│   ├── fetch_data.py     # yfinance データ取得
│   ├── dashboard.py      # HTML生成
│   └── main.py           # エントリポイント
├── tests/
│   └── test_kiriban.py   # 計算ロジックのユニットテスト
├── docs/                 # GitHub Pages配信用（自動生成）
│   ├── index.html
│   └── signal.json
├── .github/workflows/
│   └── daily_signal.yml
└── requirements.txt
```

**設計方針**: 計算ロジック (`kiriban.py`) は純粋関数で、データ取得と完全に分離。
これでバックテスト・ユニットテストが書きやすく、将来別のデータソース
（Rakuten / SBI / J-Quants）に切り替えるのも容易。

## ローカル実行

```bash
pip install -r requirements.txt
python src/main.py              # docs/index.html と docs/signal.json を生成
python tests/test_kiriban.py    # テスト
```

## デプロイ

1. GitHubにpushし、**Settings → Pages → Source: GitHub Actions** を選択
2. 平日 8:40 JST に自動でダッシュボード更新
3. `workflow_dispatch` で手動トリガーも可能

## ⚠️ ディスクレーマー

本ツールは個人研究用の情報提供のみを目的としています。

- 全シグナルは過去のアノマリーに基づく**仮説**であり、統計的有意性は保証されません
- 実運用前に必ず自前でバックテストし、勝率・期待値を検証してください
- 取引の判断・結果は全て自己責任です
